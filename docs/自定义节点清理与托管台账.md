# 自定义节点清理与托管台账（DEFAULT_NODES 的“只增不减”问题）

> 适用场景：注释/删除 `entrypoint.sh` 的 `DEFAULT_NODES` 一行后，希望 `custom_nodes/` 下
> 对应目录同步清理；以及误删后的恢复、硬删除、暂停清理等操作。
> 实现时间：2026-09-30，随 `entrypoint.sh` 托管台账机制上线（`PRUNE_CUSTOM_NODES`）。
> 环境：ComfyUI 0.38.0（容器内 `nodes.py` / `main.py` 行为已验证）。

---

## 一、问题与根因

`entrypoint.sh` 原先只驱动三件事：克隆缺失节点、更新已有节点、安装 requirements，
**从不删除目录**。结果是：

- 注释掉 `DEFAULT_NODES` 一行 → 磁盘目录仍在，ComfyUI 下次启动照样加载它；
- 想清理只能手工 `rm -rf`，容易误删用户手工安装的节点。

两个硬约束决定了不能简单“扫目录做差集”：

1. `custom_nodes/` 下存在非托管目录，例如：
   - `easy_qwenEdit_2509-main`：无 `.git` 的手工放置目录；
   - `comfyUI-Realtime-Lora`：ssh remote、从未进过 `DEFAULT_NODES`；
   - `RegioCraft`：已注释但历史遗留的目录。
   按“不在列表就删”扫描会把它们一并干掉。
2. 隔离目录不能随便放：ComfyUI 扫描 `custom_nodes/` 顶层时**只跳过 `*.disabled` 后缀**
   （`nodes.py:2377`、`main.py:210`，2026-09-30 容器内 0.38.0 源码），
   隐藏目录（如 `custom_nodes/.trash/`）不会被跳过，会每次启动尝试 import 并刷 warning。

## 二、机制设计

### 托管台账 `custom_nodes/.managed_nodes`

纯文本，每次启动由 entrypoint 原子重写：

```
# name|repo|state  state: active=已启用 / disabled=entrypoint 软删除（可自动恢复）/ held=手工禁用（不自动恢复）
ComfyUI-KJNodes|kijai/ComfyUI-KJNodes.git|active
RegioCraft|zeus-onl/RegioCraft.git|disabled
```

- **只有台账里的节点才会被自动处理**；手工安装的目录永远不碰；
- 手工删掉某行 = 解除托管（该目录不再被自动清理）；手工加行 = 纳管；
- 首次运行自动“收养”：`DEFAULT_NODES` 中已存在、且 `git origin` 与列表匹配的目录
  （兼容 `GH_PROXY` 前缀与 ssh 形式的 origin）；origin 不匹配只告警、不纳管。

### 状态机（每次启动顺序：clone/恢复 → 清理+写台账 → requirements）

| 场景 | 动作 | 台账 state |
|---|---|---|
| 在列表 + 目录存在 | 不动 | `active` |
| 从列表移除 + 目录存在 | 默认改名 `<name>.disabled`；`delete` 模式 `rm -rf` | `disabled`（delete 则删记录） |
| 重新加入列表 + 存在 `<name>.disabled` 且 state=disabled | `mv` 恢复，不重新下载 | `active` |
| 目录是 `.disabled` 但 state 不是 disabled | 视为手工禁用（Manager 等），**不自动恢复**，clone 段跳过 | `held` |
| 列表里但目录和 `.disabled` 都没有 | 正常克隆 | `active` |
| 目录与 `.disabled` 同时存在 | 告警不动作，人工处理 | 保留原记录 |

### 策略开关

`PRUNE_CUSTOM_NODES`（默认 `disabled`）：

- `disabled`：软删除（改名 `.disabled`，可逆，节点自下载的模型/缓存不丢）；
- `delete`：直接删除目录（回收空间；重新启用时重新克隆）；
- `off`：只维护台账，不处理磁盘；
- 未知值：告警并回退 `disabled`。

清理动作记录在 `custom_nodes/.pruned.log`（时间戳 + 动作 + 节点名）。

### 代码位置（entrypoint.sh）

- 函数集中在标记 `# >>> managed-nodes-helpers` … `# <<< managed-nodes-helpers` 之间：
  `manifest_state()` / `node_origin_matches()` / `sync_custom_nodes()`；
  本地测试脚本按此标记提取函数（标记勿删）；
- clone 段内联“恢复 `.disabled`”逻辑（`=== Cloning missing custom nodes ===`）；
- 启动时调用 `sync_custom_nodes`（`=== Syncing managed custom nodes ===`）。

## 三、常用操作

```bash
# 移除节点：注释 DEFAULT_NODES 对应行 → 重启
docker restart comfyui-docker          # 目录改名为 <name>.disabled，ComfyUI 不再加载

# 恢复：取消注释 → 重启                # 自动改回原名，不重新下载

# 硬删除 / 暂停清理：编辑 .env 后必须“重建容器”才生效（env 在创建时注入）
PRUNE_CUSTOM_NODES=delete              # 或 off
docker compose up -d --force-recreate

# 查看台账 / 清理日志
cat custom_nodes/.managed_nodes
cat custom_nodes/.pruned.log

# 解除单个节点的托管（之后不再被自动清理）
$EDITOR custom_nodes/.managed_nodes    # 删除对应行
```

历史遗留的一次性处理（已注释、从未入台账，如当时的 `RegioCraft`）：
手工在 `.managed_nodes` 追加 `RegioCraft|zeus-onl/RegioCraft.git|active`，
重启后 entrypoint 按正常流程软删除；或按 README 的“取消注释启动一次 → 再注释启动一次”。

## 四、验证（可复现）

### 单元测试（宿主机，无需容器）

```bash
bash scripts/test_managed_nodes.sh
```

从 `entrypoint.sh` 提取真实函数，用假目录覆盖 11 个场景：收养、origin 不匹配保护、
软删除、off、delete、未知值回退、held（手工禁用）语义等。

### 真机验证步骤（每次重启前后核对）

1. 重启一次完成台账自举：日志出现 `=== Syncing managed custom nodes ===` 与
   `Manifest updated: ... (N managed nodes)`，且 `custom_nodes/` 目录列表无变化；
2. 注释一个小节点（示例用 `ComfyUI-EulerDiscreteScheduler`）→ 重启：
   日志 `Disabled: <name>`、目录改名 `.disabled`、`.pruned.log` 有记录；
3. 取消注释 → 重启：日志 `Restored: <name> (从 <name>.disabled 恢复，未重新下载)`；
4. `delete` 模式：用 dummy 目录 + 台账记录验证目录被删、记录消失。

### 日志判读技巧

`docker logs` 会混着多次启动的历史记录，判断“本次是否还加载某节点”要按进程启动时间切分：

```bash
# 容器内最新 ComfyUI 进程启动时刻
docker exec comfyui-docker sh -c "ps -eo pid,lstart,args | grep -v grep | grep 'main.py'"
# 只看该时刻之后的日志；.disabled 节点不应出现在 “Import times” 列表里
docker logs --timestamps comfyui-docker 2>&1 | grep -a -i "<节点名>"
```

注意 `docker logs --since` 的时区换算可能与容器日志时间戳（UTC）不一致，用 `ps` 时间对齐最稳。

## 五、已知边界与坑

- **手工禁用 vs 自动软删除**：两者都是 `<name>.disabled`，最初实现无法区分，
  导致“手工禁用节点第二轮启动被自动恢复”。现用台账 `held` 状态区分：
  只有 entrypoint 自己软删除的（`disabled`）才会被自动恢复；
- 被移除节点的 **pip 依赖不会卸载**（可能被其他节点共用，无法安全回收）；
- 修改 `DEFAULT_NODES` 里的**目录名**（而非增删）等价于“旧节点软删除 + 新节点克隆”；
- `PRUNE_CUSTOM_NODES` 写在 `.env` 时，`docker restart` 不重读 `.env`，
  必须 `docker compose up -d --force-recreate`；
- 目录与 `.disabled` 同时存在时不动作（告警），避免猜错用户意图。
