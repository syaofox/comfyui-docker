# 节点依赖冲突与核心包锁定（transformers / huggingface-hub / diffusers）

> 适用场景：新增自定义节点后，启动时出现「别的节点 IMPORT FAILED」，
> 尤其是 `ImportError: cannot import name 'get_cached_repo_tree' from 'huggingface_hub'`
> 这类由共享依赖被降级引发的问题。
> 实例：加入 `DocWorkBox/ComfyUI-AuK_Doc` 后，`ComfyUI-SDPose-OOD` 导入失败（2026-09-25）。

---

## 一、症状与根因

启动日志特征：

```
RuntimeError: Failed to import diffusers.pipelines.pipeline_utils ...:
cannot import name 'get_cached_repo_tree' from 'huggingface_hub'
[INFO]    1.6 seconds (IMPORT FAILED): /home/comfy/app/custom_nodes/ComfyUI-SDPose-OOD
```

依赖链：

- `diffusers>=0.40` 需要 `huggingface-hub 1.x` 的 `get_cached_repo_tree`；
- `transformers 4.x` 强制 `huggingface-hub<1.0`；
- `ComfyUI-AuK_Doc/requirements.txt` 写了 `transformers>=4.52.0,<5`，
  于是 uv 在安装它时把环境整体降级：

  ```
  - huggingface-hub==1.29.0  + huggingface-hub==0.36.2
  - transformers==5.16.1     + transformers==4.57.6
  - tokenizers==0.23.1       + tokenizers==0.22.2
  ```

  然后 `diffusers 0.40` 在下次 import 时挂掉。

所有节点共用同一个系统 Python 环境，任何节点的 requirements 都可能改共享包版本；
`entrypoint.sh` 的 constraints 原先只锁 `torch/numpy/cupy/onnxruntime`，没覆盖 transformers 系。

## 二、诊断命令

```bash
# 1) 谁在报错、报什么
docker logs --since "$(docker inspect -f '{{.State.StartedAt}}' comfyui-docker)" comfyui-docker 2>&1 \
  | grep -E "IMPORT FAILED|Cannot import"

# 2) 找降级发生的那次安装（- / + 行即被换掉的版本）
docker logs comfyui-docker 2>&1 | grep -nE "Installing requirements for|^ [-+] (huggingface-hub|transformers|tokenizers|diffusers)="

# 3) 当前实际版本与包之间的约束
docker exec -i comfyui-docker python3 - <<'EOF' 2>/dev/null
import importlib.metadata as md
for p in ("transformers","huggingface-hub","tokenizers","diffusers","funasr","modelscope"):
    print(p, md.version(p))
print([r for r in md.requires("transformers") or [] if "huggingface" in r])
EOF

# 4) 确认 diffusers 的报错点是否为 hub 版本问题
docker exec comfyui-docker python3 -c "import huggingface_hub as h; print(h.__version__, hasattr(h,'get_cached_repo_tree'))"
```

## 三、修复：constraints + 节点 requirements 过滤（已落地 entrypoint.sh）

`entrypoint.sh` 两处改动：

1. `write_constraints()` 增加锁定 `transformers` / `huggingface-hub` / `tokenizers`
   （用 `importlib.metadata` 读版本，缺失的包自动跳过，不再因 import 失败放弃整个 constraints）：

   ```
   transformers==5.16.1
   huggingface-hub==1.29.0
   tokenizers==0.23.1
   ```

2. 节点 requirements 的 `FILTER_PATTERN` 增加这四个包（含 `diffusers` 之外的共享包），
   与 `torch` 同等待遇：**节点 requirements 里的这些行会被剔除，版本只由 constraints 决定**。
   包名后要求是「非包名字符」（空白/行尾/版本符等），避免误伤
   `transformers_stream_generator` 这类同前缀包，并兼容 CRLF 行尾：

   ```
   ^[[:space:]]*(torch|torchvision|torchaudio|transformers|tokenizers|huggingface[-_]hub|
   cupy-cuda[0-9]*|onnxruntime-gpu|llama[._]cpp[._]python)([^A-Za-z0-9_.-]|$)
   ```

   constraints 内容变化会让所有节点的 hash 失配，重启后自动重装一遍（uv 命中缓存，很快）。

## 四、验证

```bash
# 版本已回到 5.x 一套
docker exec comfyui-docker python3 -c "import huggingface_hub as h, transformers as t, diffusers; print(h.__version__, t.__version__, diffusers.__version__)"

# 启动日志无 IMPORT FAILED，目标节点都在
docker logs --since "$(docker inspect -f '{{.State.StartedAt}}' comfyui-docker)" comfyui-docker 2>&1 \
  | grep -E "IMPORT FAILED|SDPose-OOD|AuK_Doc"

# API 里能看到节点
curl -s http://127.0.0.1:8188/object_info | python3 -c "import json,sys; d=json.load(sys.stdin); print(sum('SDPose' in k for k in d), sum('AuK' in k for k in d))"
```

## 五、注意与备选方案

- 若某节点**运行期**确实不兼容 `transformers 5.x`（本次 AuK_Doc 的
  `Qwen2_5OmniProcessor` 等导入验证通过），两条退路：
  1. 降级 `diffusers` 到与 `huggingface-hub 0.36` 兼容的版本，并把
     `transformers/hub/tokenizers` 一起锁到 4.x 一套；
  2. 给该节点单独建 venv（改动大，不推荐）。
- 升级 ComfyUI 本体后若新 requirements 要求更高的 `transformers`，
  constraints 会造成冲突、安装失败并提示；此时手动抬高 `write_constraints()` 里的锁定版本即可。
- 更新节点依赖用 `FORCE_CUSTOM_NODE_REQUIREMENTS=1 docker restart comfyui-docker`，
  但过滤规则与 constraints 始终生效。
